# Threat model

Primary threats include deadline bypass, role manipulation, Sybil voting, judge collusion, draft leakage, and prize bait-and-switch. Mitigations include server-clock checks, opaque revocable sessions, database-scoped assignments, deterministic gallery ordering, audit logs, and immutable prize-floor validation after launch.

## Webhooks (Tier 4.5): SSRF and replay

Webhooks are the first feature in this app that calls a URL an organizer supplies, rather than an operator-provisioned compose service (contrast with the SeaweedFS calls elsewhere, which target a fixed internal hostname). An organizer-controlled URL is an SSRF vector: without checks, "register a webhook" becomes "make this server issue an authenticated-looking HTTP request to anywhere I choose," including the Postgres/SeaweedFS containers or a cloud metadata endpoint if this were ever deployed elsewhere. Mitigations (`src/server/webhook-url-guard.ts`): scheme restricted to `http(s)`; a literal blocklist of compose service hostnames (`postgres`, `seaweedfs`, `app`, `dev`, `localhost` — these resolve fine from inside the compose network, so DNS alone can't catch them); every resolved IP address checked against loopback/private/link-local ranges (IPv4 and IPv6). The check runs twice — once at registration, once again immediately before each delivery attempt — because a hostname that resolved safely at registration could be repointed at an internal address by delivery time (DNS rebinding); checking once and trusting it thereafter would leave that window open. `WEBHOOK_ALLOW_PRIVATE_HOSTS=true` disables all of this for local testing, off by default, same shape as `ALLOW_DESTRUCTIVE_DB_TESTS`.

Deliveries are HMAC-SHA256 signed over `{timestamp}.{canonical body}` (not the body alone), sent as `X-Dogfood-Timestamp` + `X-Dogfood-Signature`. A receiver that checks the timestamp is recent (not just that the signature matches) can reject a replayed delivery captured and resent later. This app doesn't ship a receiver, so timestamp-freshness enforcement is guidance for whoever implements one, not something this codebase verifies itself.
